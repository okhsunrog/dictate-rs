# Диктовка: руководство

Dictate записывает речь через PipeWire, отправляет законченную запись на
распознавание, затем редактирует текст языковой моделью. Интерфейс написан на
Qt Quick/QML, связь с Rust реализована через Qt Bridge. Язык интерфейса — русский.

## Установка и первый запуск

На NixOS:

```sh
git clone https://github.com/okhsunrog/dictate-rs.git
cd dictate-rs
nix develop
just demo
just settings
```

Демо показывает пример текста без записи и сети. В настройках укажи адрес
сервиса с `/v1`, ключ API и модель редактирования. Приложение не подставляет
личный сервер или модель по умолчанию. Для установки бинарника и пункта меню
в `~/.local` выполни `just install`; для разработки запускай через Nix-окружение.

На других дистрибутивах нужны Rust 1.88+, C++ toolchain, pkg-config, Qt 6.10+
с private headers, Qt Declarative, Qt Wayland, LayerShellQt и QML-модули
qqc2-desktop-style, Kirigami и Sonnet. Команда сборки — `cargo build --release --locked`.
Во время работы также нужны `pw-record` и `wl-copy`.

Сервис должен поддерживать `audio/transcriptions` с моделью `chatgpt-transcribe`
и `responses` для выбранной модели редактирования. Модель должна принимать
`reasoning.effort=none`. Подробный формат запросов описан в [README](../README.md#service-configuration).
Произвольный сервис с похожим API не обязательно поддерживает этот контракт.

## Запись

1. Проверь аппаратный выключатель микрофона и системное устройство ввода.
2. Запусти `dictate` или нажми назначенную горячую клавишу.
3. Говори: на плашке видны время и уровень звука.
4. Запусти `dictate` повторно или нажми «Завершить».
5. Окно откроется сразу после остановки. Сначала появится исходная расшифровка,
   затем отредактированный текст.
6. Проверь результат и нажми «Копировать».

Можно произносить исправления: например, «в среду в три, нет, в четверг в два».
Редактор старается сохранить окончательный смысл. Живой потоковой расшифровки нет.
Максимальная длительность записи — десять минут, размер запроса — до 25 МиБ.

## Окно, команды и история

- `dictate show` открывает окно без записи; `dictate settings` открывает настройки.
- Ctrl+Enter копирует текст и скрывает окно. Escape только скрывает окно.
- Крестик завершает процесс, останавливает запись и отменяет обработку.
- «Ещё» открывает историю, исходную расшифровку и повтор обработки.
- Исходник доступен только для чтения. Переключение не теряет ручные правки.
- Поздний ответ модели не заменяет уже внесённые ручные правки.
- Последние десять черновиков хранятся только до выхода из приложения.

`dictate clipboard` начинает запись с копированием результата без предпросмотра.
`dictate paste` начинает запись с автоматической вставкой. Повторный запуск
останавливает текущую запись и сохраняет режим, выбранный при старте.
Команды `cancel`, `retry` и `quit` управляют уже работающим экземпляром.

## Горячая клавиша и размер окна

В Niri добавь в конфигурацию, выбрав свободное сочетание и свой абсолютный путь:

```kdl
binds {
    Mod+D { spawn "/home/YOUR_USER/.local/bin/dictate"; }
}

window-rule {
    match app-id=r#"^ru\.okhsunrog\.dictate$"#
    open-floating true
    open-maximized false
    open-fullscreen false
    default-column-width { fixed 640; }
    default-window-height { fixed 480; }
}
```

В Plasma назначь ту же команду через «Параметры системы → Клавиатура → Комбинации
клавиш». Не добавляй обычный запуск в автозагрузку: он сразу включает запись.

## Автовставка

В настройках нажми «Подключить автовставку» и подтверди системный диалог.
Нужен RemoteDesktop-портал с поддержкой libei/EIS. Это зависит от рабочего стола:
обычная конфигурация порталов Niri может его не предоставлять. Тогда используй
копирование и ручной Ctrl+V. Смена интерфейса приложения это ограничение не устраняет.

Если портал разрешает, приложение сохраняет токен для следующих запусков.
Режим вставляет текст в приложение, активное в момент готовности результата.
Не переключай целевое окно до завершения обработки. Для терминала включи
совместимость с Ctrl+Shift+V. При ошибке вставки текст остаётся в буфере обмена.

## Настройки и данные

Настройки находятся в `~/.config/dictate/config.toml`; пример —
[config.example.toml](../config.example.toml). Права каталога — `0700`, файла — `0600`.
Ключ, введённый в настройках, хранится в этом файле открытым текстом.
`DICTATE_API_KEY` и `DICTATE_BASE_URL` переопределяют значения без сохранения в файл.

Пустой язык означает автоопределение. Пустой микрофон означает системный источник
PipeWire. При необходимости укажи имя узла из `wpctl status -n`.

Аудио и история находятся в памяти процесса. Для повтора доступна только последняя
запись; новая запись заменяет её. После выхода данные исчезают. Аудио и текст
отправляются выбранному сервису; дальнейшее хранение зависит от этого сервиса.
Отмена запроса не гарантирует отмену уже начатой обработки на сервере.

## Если что-то не работает

- «Речь не распознана»: проверь аппаратный выключатель, mute, источник и полоску
  уровня. После исправления повтори обработку или сделай новую запись.
- Ошибка распознавания: аудио сохранено в памяти для кнопки «Повторить».
- Ошибка редактирования: исходный текст остаётся доступным; повтор запускает
  только редактор, без повторной отправки аудио.
- Нет окна: проверь наличие QML-модулей. Для вывода ошибок Qt используй
  `QT_FORCE_STDERR_LOGGING=1 dictate show`.
- Не вставляется текст: проверь поддержку RemoteDesktop-портала. Готовый текст
  можно скопировать вручную.

Для проверки разработки есть `just check`, `just ui-smoke` и `just wayland-smoke`.
Они используют искусственное аудио и локальные ответы, без физического микрофона
и платных запросов. Последняя команда требует Wayland-сессию и Niri.
